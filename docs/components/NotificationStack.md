# NotificationStack

The ephemeral notification window lets the person read a new result and, when its source offers a default action, open that source without interrupting the application underneath. The host owns which notifications exist, their expiry and every consequence; the stack owns the rendered rows and forwards each card's intent.
states: input is newest-first, rendered oldest-first from top to bottom; active rows, overflow-evicting snapshots, the retained last body, and empty. A retiring row is paint, not an input target; a same-id update refreshes content and default availability in place and never replays the entrance.
look: rows are `bodied` cards by default, `rowSpacing` (`space2`, 8 px) apart and one `Style.rolloutPadding` (16 px) inside the rollout that holds them, so `Style.radiusBody` is concentric with the rollout's corners; `bodied: false` gives boxless rows with a divider. `bodied`, `bodyRadius` and `rowSpacing` are forwarded without a styling policy of the stack's own
actions: a card reports dismiss, hover and `primaryTriggered(entry)`; the stack forwards `dismissRequested(entry)`, `hoverChanged(entry, hovered)` and `primaryActionRequested(entry)`, the last only for an active eligible row whose host still offers `default`. It never resolves an action id or applies a consequence. `targetForNotification(id)` and `cardGeometry()` give a host the row and its mapped rectangle, `eligible` false for a retiring or clipped row
pointer: the card owns every route (hover lifts and opens it, the dismiss button, the middle click, a swipe that follows the hand, the body tap); the stack claims no event and no wheel
keyboard: a row is a Tab stop only while a primary action exists and the host has given the popup focus; a popup window without keyboard focus has no native keyboard route, and an arrival never takes focus
screen reader: rows are named buttons or static text by their card; the stack adds no role
size: width follows the cards (`Style.notificationWidth`), height the real row sizes plus the gaps minus the evicting share; the gap is added once per departing row to the eviction shift so survivors land where the shift stops; a long body opens to the bounded viewport, so one row grows by at most 60 px and the rows below it move by the same, gaps unchanged
tokens: notificationWidth, rowSpacing, rolloutPadding, radiusBody, `Motion.revealSmall` and the reveal curve; rows bring their own
motion: one reveal-curve eviction shift; row entrance and expansion supply their animated heights to the layout directly, no Column move runs during an eviction; a frozen row is excluded from the "a height is still moving" test; a departure still sliding when the window empties is held at its offset so the retained body keeps its extent, and an arrival releases the hold. Measured on the real frames: an arrival is 11 frames in 164 ms and a hover opening 15 frames in 230 ms, both at 16.4 ms
expected: a hover over any row is visible (the lift) and reported once, also while the pointer crosses the dismiss button; dismiss, primary and key routes each report once; a retiring or cleared row refuses input and keeps its picture
not designed: history, search, grouping, card content, lifetime and expiry; use NotificationCenter, NotificationCard or the host
